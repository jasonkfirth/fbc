# Owned continuations, November 3, 2026

Continuation addresses and indirect jumps account for 1,820 GCC warnings, 85%
of the accepted total. The same occurrences produce 1,820 Clang warnings.
The selected Scorched Earth graphics, VNC UI and Stunts data profiles contain
350 of them. These are shared control-flow contracts rather than independent
source mistakes.

## Standalone dispatch was rejected

The first current-source candidate replaces known local label addresses with
distinct object identities and dispatches them through explicit C branches.
References and transfers still evaluate their operands once. Opaque procedures
retain their GNU representation. The representation is chosen after the whole
procedure is emitted so later assembly cannot split its contract.

The three selected project object checks lose all 350 label observations under
both C tools. GCC's possible-uninitialized count in the graphics profile changes
from 66 to 65. The other 65 observations are not repaired by local dispatch.

The real ERROR comparison rejects this change on its own. Both providers pass
all 32 local cases, but the accepted compiler passes 44 of 64 total cases while
the token candidate passes 32. Twelve currently passing cross-procedure cases
fail. No canonical source was changed to adopt this candidate.

The receipt is `build/c-emitter-continuation-tokens-20261103/summary.json`.

## Current ownership integration

The owned r12 fragments were rebased onto the latest qualified compiler,
preserving the startup grouping, native pointer arithmetic and named byte-copy
slots. The only textual merge conflict was at unit initialization: both the
ERROR state reset and startup-group initialization are retained. Exact current
preimages and the failed merge are recorded.

The owner-only provider builds two fresh modules against the current 222-object
remainder. The combined provider adds local token transport. Ordinary procedures
and outlined ERROR callbacks share continuation declaration, dispatch and pool
cleanup. Both affected modules pass GCC and Clang, and strict source-only lint
passes the five combined source files and two mixed-module fixtures.

Both private providers pass 256 native lifetime executions and 20 Win32 object
checks, binding 407 SDK headers. Cases include the original global and LOCAL
ERROR modes, owner return and recursion, registration timing, worker transfer,
handler GOSUB, fixed/dynamic arrays and const results. These are fresh executions
against the current source integration, not adoption of historical results.

The combined three-project admission removes 351 GCC observations and 350 Clang
label observations. It adds 51 Clang missing-noreturn observations from the
private unsupported-resource callbacks, so the net Clang reduction in this
sample is 299. No diagnostic option is disabled. No project execution is claimed.

## Mixed modules prevent promotion

The mixed-module test compiles main and worker independently. It checks both
directions with both C producers, GCC/Clang, GNU11/GNU23 and O0/O2, using fresh
runtime objects. GAS64 object identities are unchanged between providers.

| Handler owner | Worker | Accepted passes | Combined passes |
| --- | --- | ---: | ---: |
| C | GAS64 | 8 / 16 | 16 / 16 |
| GAS64 | C | 12 / 16 | 0 / 16 |

The second direction introduces twelve failures. Its C dispatch cannot consume
the legacy GAS handler address; GAS also expects executable continuation
addresses. Local data tokens do not provide that bridge. This remains a compiler
and runtime interoperability requirement, not permission to require all callers
to use the C backend.

The initial mixed fixture incorrectly defined its shared marker privately.
The failed link, object symbols and exact fixture correction are retained. The
table comes from the corrected public definition and actual native executions.

A separate ownership-only follow-up preserves executable label addresses. It
passes 16/16 C-owner/GAS64-worker cases and 12/16 GAS64-owner/C-worker cases,
versus 8/16 and 12/16 in the accepted control. It introduces no new failures;
four existing opposite-direction failures remain. This provider predates the
record-offset guard checkpoint and has no complete current-source qualification.
Its receipt is `mixed-owner-native/receipt.json` in the same private stage.

The combined provider remains private. Managed UDT and partial-construction
unwinding, shared ordinary/handler regions, remaining capture/ABI cases, threading,
semantic source facts, complete compiler self-hosting and broader source/target
qualification are also unfinished. The private unsupported-resource callback
terminates; it is not a production unwinder.
